Security Flow

1. FE → POST /auth/login → IAM
2. IAM mint JWT (FernJwtClaims)
3. Gateway validates via FernJwtService + Redis acceptance check
4. Gateway relays X-Fern-Principal header downstream
5. Services extract FernPrincipal, check PermissionCodes + ScopeRoots

Scope Model (Multi-Outlet)

scope_roots: system | regions[] | outlets[]
accessible_scope: intersection với policy

Frontend ScopeChecker → hasScopeAccess() → determines menu visibility per outlet

Backend Authorizer → validate principal scope vs resource outlet

Auth & Multi-Outlet Scope Model SECURITY

JWT Claims (FernJwtClaims)

{
  "sub": "user-uuid",
  "jti": "token-uuid",
  "principal_type": "USER | SERVICE",
  "roles": ["string"],
  "permissions": ["string"],
  "scope_roots": {
    "system": false,
    "regions": ["region-uuid"],
    "outlets": ["outlet-uuid"]
  },
  "accessible_scope": {
    "regions": [...],
    "outlets": [...]
  },
  "policy_version": 5,
  "scope_version": 3,
  "auth_time": 1743123456,
  "iss": "fern-iam",
  "aud": "fern-gateway"
}

Frontend ScopeChecker Logic

hasScopeAccess(principal, requirement):
  if principal.scopeRoots.system → true
  
  effectiveScope = principal.accessibleScope
                   ?? principal.scopeRoots
  
  if requirement.type === 'region':
    return effectiveScope.regions
           .includes(requirement.regionId)
  
  if requirement.type === 'outlet':
    return effectiveScope.outlets
           .includes(requirement.outletId)

Token Lifecycle & Redis

Login: IAM tạo access_token (short-lived) + refresh_token, lưu jti vào Redis với TTL

Gateway Validation: FernJwtService parse JWT → RedisFernTokenAcceptanceValidator check jti còn trong Redis → nếu không có → 401

Logout: IAM xóa jti khỏi Redis → tất cả gateway requests sẽ bị reject

Refresh: FE gọi POST /auth/refresh với refresh_token → IAM phát access_token mới, jti mới

FE 401 Handler: httpClient intercept 401 → gọi refresh.service.ts → retry original request

Multi-Outlet Authorization Pattern (Backend)

SYSTEM ADMIN

scopeRoots.system = true → full access tất cả regions và outlets. Không cần check scope cho từng resource

REGIONAL MANAGER

scopeRoots.regions = [r1, r2] → backend Authorizer gọi org-service /internal/scopes/expand để lấy outlets trong region → intersect với accessible_scope

OUTLET STAFF

scopeRoots.outlets = [o1] → chỉ thấy và thao tác data của outlet mình. POS session, inventory, attendance đều filter theo outletId

SERVICE TOKEN

principal_type = SERVICE → dùng cho internal service-to-service calls (report-service gọi hr-service, pos-service gọi inventory-service)
